# 静默失效检查清单

*出自「用 AI 做游戏」第 1 期：零报错，半死不活。*

我们第一次完整模拟《缄默都会》，40 个机器人打完一整季：十二万两千条命令，零报错。可游戏有一半根本没发生。什么都没崩，每一处坏掉的地方，都是规则在一丝不苟地照着写好的做。下面是我们现在每次都过一遍的清单。

## 一、让这一整类失败大声报出来

发现一个静默失效，修掉它之后，再加一道检查，把**这一类**的失败全拦住。

- [ ] 数据里用到的每个枚举值，代码都认识；不认识，服务器就拒绝启动。
- [ ] 规则里写到的每个变量，都能对上真东西；对不上，服务器就拒绝启动。
- [ ] 每条配方要的主牌类型，至少有一张牌能匹配。
- [ ] 表里该出现在世界里的东西（NPC、组织、职位），开局真的生成了。
- [ ] 规则在执行命令时也要查，不能只在生成选项时查一次。

## 二、证明每个测试真的会红

- [ ] 每个修复配一个测试。
- [ ] 把修复撤掉，看着测试变红。
- [ ] 再放回去，看着它变绿。

从来没红过的测试，什么也没证明过。

## 三、别信「零报错」

要问的是：我设计的那件事，真的发生了吗？把每一个没用上的行动分进四个桶：

| 桶 | 意思 | 怎么办 |
|---|---|---|
| 1. 从没出现在选项里 | 没人拿到过能驱动它的牌 | 牌流问题，多半是设计漏洞 |
| 2. 出现了，但做不了 | 牌有了，门槛从没过 | 查门槛为什么过不去 |
| 3. 能做，没人选 | 做得了，只是没人挑 | 没关系，那是策略 |
| 4. 一做就出错 | 有人做了，结算时出错 | 必须修 |

- [ ] 统计走玩家真正看见的那份选项，不要另写一套规则来算。
- [ ] 报错和失败分开报：判定没过是规则，报错是漏洞。
- [ ] 有报错就让工具失败退出，不要只在报告里印一行。
- [ ] 诊断工具的数字，先确认它认得全部来路再信。工具自己的盲区会造出假的头号漏洞。

## 四、别在测试里写死精确的数

- [ ] 把「必须正好 14 组」改成「代码要用的那几组都在，而且不是空的」。
- [ ] 用下限挡真正的事故：整张表没读进来，或者只读了一半。

精确的数每次正常改表都会红，红几次之后，大家就学会了直接把数字改大。到那时候，它就只剩噪音了。
